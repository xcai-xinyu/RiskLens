# ADR 0004 — P3 durable single-instance tasks and product surfaces

Authorized by user after explicit H2 approval of P2 attempt-002 offline/deterministic scope. Keep P0/P1/P2 schemas, formulas, Verifier and sealed evidence unchanged. Add FastAPI and Streamlit, as already specified; lock added packages in the existing WSL venv.

CLI → ResearchService and UI → API → ResearchService. Routes/UI do not contain research, financial or verification logic. The service owns a bounded in-process FIFO (one worker, eight waiting requests by default). Workflow execution remains the P2 bounded worker; no live/demo fallback. Current API stage is coarse research_workflow while the existing worker executes, with queued and report/failed/interrupted boundaries explicit. Calls in progress are unknown, not fabricated zero; final counters persist.

P3 RunRepository is a separate SQLite authority from the P1 document Repository. Add runs/reports/schema_versions tables only to the P3 database; do not migrate existing document databases. Persist full validated RiskReport snapshots, citations, metric inputs, verification/lineage, versions and metadata. Historical reads do not initialize Chroma or depend on original temporary stores. The task UUID is the API/report ID; the P2-generated ID remains workflow_run_id provenance. Atomic report+terminal state transaction, parameterized queries and a local file lock enforce single database owner. No multi-instance/distributed queue claim.

SPEC ambiguity: internal interrupted is mapped to external status=failed, stage=interrupted, errors[].code=process_interrupted; the public status enum stays queued/running/completed/partial/failed. On startup and shutdown, abandoned queued/running records are interrupted, not silently resumed. Retry requires explicit resubmission. completed maps from complete reports; partial includes partial/insufficient_evidence reports with no execution errors; failures remain separately failed. A failed run may retain its explicit failure/gap report, without implying HIGH risk.

Comparison preserves dates, source coverage/hashes, corpus, mode, model/provider, prompt/content hashes, rubric/formula/verification versions and completeness. Differences/unknown metadata produce not directly comparable; no automatic risk-direction claim. All UNKNOWN remains visibly distinct from LOW. Evaluation UI is planned P4, no fake results.

Alternatives rejected: copying workflow logic into UI/API, relying on Chroma for history, extending public run status without documenting it, or automatically restarting abandoned work. Rollback: continue --stage p0/p1/p2; P3 is additive. Tests: API lifecycle/status/export/history, locked ownership, SQLite restart/interrupted recovery, comparison, shared service boundary and Streamlit AppTest/HTTP smoke. Browser interaction evidence is reported separately from AppTest simulation.
